# RPC console argument privacy

The parser redacts arguments before the console stores request rows or recall
history. The same filtered command supplies both surfaces, including after Clear.
Execution receives the original command on its existing worker. Original input
must not be stored to repair history navigation.

The policy covers the pinned Core Qt Widgets history filter and addhdkey, which
accepts an extended private key. A regression reads the pinned Core policy and
requires review when that list changes. A separate matrix covers all nine app
commands in space-separated, quoted functional, uppercase and nested notation.
Ordinary commands keep their useful arguments.

Tests independently verify exact backend methods and typed parameters, request
rows and safe recall, native Return/Clear/Up/Down, locked disposable wallets and
ordinary controls. Real GUI processes also inspect output, Core debug logs,
shutdown stderr and exit status in both runtime wallet modes. Only owned fixture
sentinels are used. Arbitrary RPC reply payloads may themselves contain sensitive
data; this policy concerns retained command arguments.

Full RPC operation, session and lifecycle ownership remains the R38/M22 migration.
