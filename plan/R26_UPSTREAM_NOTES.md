# R26 public review adapter upstream note (draft; focused gate pending)

Core pin44901d8f64cb617714707bd025ecd83f108353c2 remains unchanged. M26's source reader, local draft command ledger and view ownership are application responsibilities; atomic local URI replacement requires no Wallet API addition.

The PSBT review target currently adapts public Wallet reads using `psbtwork::PrepareReview`. Wallet does not supply one immutable, typed, non-mutating review result containing assessed PSBT, owned-input/signability facts, fee/provenance, known-transaction status and policy observation with a documented snapshot boundary. The app composes those existing reads on Native, checks exact unsigned commitments and captures the original opening plus review/view fence. It stores a per-child immutable result before acknowledgment transport and only projects that result into its original view. No implicit Sign, commit or broadcast occurs; later protected actions revalidate their own authority. A closed or successor view cannot install a late result. Lost acknowledgments query the original bounded ledger without creating another review.

This is an optional upstream improvement for M26, not a request to change Core or a required capability blocker. Independent RPC or node changes can make wallet/policy observations stale; the app does not claim an atomic backend snapshot, device identity reservation, transaction acceptance or broadcast authority. Existing R17 change-policy preview limitations and R20 unknown-commit receipt limitations remain independently tracked. The app pays for immutable result retention, exact child/review/view identities and a Native-to-GUI projection adapter.

A future public typed read-only review API should document snapshot/known-status/fee/capability consistency and preserve exact source bytes while returning a separate assessment. Suggested upstream tests: metadata/status changes during inspection, known transactions whose final txid differs from unsigned id, missing/forged prevouts, standard/nonstandard outputs, unsupported scripts, incomplete and verified complete signatures, independent RPC changes and shutdown. Replace the app composition only after the pinned public contract provides equivalent guarantees and independent focused Core/RPC tests pass. Keep the app's source and view lifecycle fences and explicit final command boundary.

Evidence is pending R26 focused qualification. No acceptance or source gate is established by this draft.
