# R35 public wallet-directory inspection adapter

The current public `WalletLoader::listWalletDir()` accepts no path and inspects the globally configured wallet directory/network. The onboarding preview must classify an inactive proposed profile without changing the running parent's settings. The inherited `wallet::ListDatabases(path)` call crossed the strict public-wallet boundary and is removed by this adapter. No Core modification or temporary private-access exception is authorized.

The app-owned helper runs in a fresh headless process. It uses public Init/Node/WalletLoader factories, child-only forced wallet-directory configuration, and the existing public startup network selection. It never calls baseInitialize/appInitMain, loads a wallet, starts the node/network, or parses wallet database formats. Exact proposed network and optional signet challenge are captured with the original absolute directory. A master-key fingerprint or a wallet identity is not inferred from the protocol request tag: that tag identifies request bytes only, while the existing revision/scheduler scope owns publication.

The Native adapter bounds request/protocol bytes and process time, handles cancellation before and after physical start, terminates/reaps the original read-only child, and reports unavailable/failed/timed-out/cancelled outcomes explicitly. A failed process is never an empty-directory success. GUI retirement and a newer proposed path cannot transfer that child or its result to another request. GUI retains only bounded cached presentation; no filesystem/Core work or wait is added there. Process completion assumes the OS can reap the terminated child; no universal OS kill deadline is promised and the original Native owner remains responsible until physical exit.

The guarantee matches public Core recognition, including empty wallet names, explicit directories, and network-specific SQLite recognition. It is an observation, not an atomic filesystem snapshot. The existing public list does not expose complete recursive scan diagnostics, a row/memory budget or a path parameter. The helper needs to be shipped alongside the application; its absence/version/transport failure is visible and has no private fallback. Full platform/configuration, packaging, exhaustive coverage and sanitizer qualification remain R42 obligations.

Proposed upstream capability: a read-only public `WalletLoader::inspectWalletDir(path, network/configuration, limits)` returning a typed snapshot/result with recognized entries (or presence), completeness, diagnostics and capacity/cancellation status, without changing global args/Params, loading wallets, reserving keys or writing the target. Core should retain its own format/network recognition. This would remove the child process and its startup cost and make cancellation/resource limits explicit at the public boundary.

Retire this adapter only after a supported pinned public interface supplies those semantics and independent tests prove valid root/default-empty identity/explicit directory/junk/wrong/custom network/no-target-write/no-parent-mutation behavior, stale-request and cancellation ownership. Remove the helper executable/protocol/process code only with that consumer migration; a new state label alone cannot supply the missing read capability.
